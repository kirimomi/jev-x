# Jev 画像判定（Vision）検証・導入判断計画書

## 1. 背景と相談の論点整理

Jev（`@typesafe-ai/sdk` v0.7.0 / `jev-1.13`・`jev-1.14`）で画像入力がサポートされたことを受け、現行の「ローカル `nsfwjs`（露出度のみ）＋ Jev（テキストのみ）」から、画像自体も Jev に判定させるべきかを検討する。

導入判断にあたり、以下の3つの論点を検証する必要がある。

### 論点①：転送量・トークン消費・レイテンシの増加
- X のタイムラインは画像・動画サムネイル付き投稿の割合が高く、すべての画像を無条件に API へ送信すると**上り通信量**と**APIトークン消費**が大きく増える。
- **対策の方向性（導入する場合）**：
  - X の CDN（`pbs.twimg.com`）のクエリを `?format=jpg&name=small`（長辺最大 680px）または 360px 程度に縮小して取得し、1枚あたり **30〜100KB 程度**に抑える（フル解像度画像は送らない）。
  - 4枚添付されていても**1枚目のみ**を送る。
  - すでにテキストや X 公式警告だけでフィルタ確定した投稿には画像を送らない。

### 論点②：X で「アダルト以外」に画像で不快になるケースは何か？
日常写真や通常のイラストで不快になるケースは少ない一方、**「本文テキストだけでは無害に見えるが、画像そのものが嫌われる」**X 特有のパターンは以下の3つに絞られる：

| ターゲット | X での具体例 | テキストのみ判定の限界 |
| :--- | :--- | :--- |
| **1. AI生成画像・動画サムネ**<br>（最大の検証価値） | 「おはよ☀️」等の短文＋**AI美女写真**、**量産型AIイラスト**、**AI生成の奇妙なバズ動画サムネ** | 本文に「AI」「ChatGPT」等の単語を含めないアカウントが多く、テキスト判定では100%すり抜ける |
| **2. 画像化されたスパム・商材** | 収益画面のスクショ、文字画像での煽り、インプレゾンビの無関係ミーム画像リプライ | 本文が絵文字のみ・短文だと判定材料が不足する |
| **3. センシティブ・露出系** | 水着・下着・過度な露出イラスト等 | 現行はローカル `nsfwjs`（約30MBのモデル）で判定しているが、肌色面積に引っ張られる誤検知がある |

> [!IMPORTANT]
> **「とにかく AI 生成画像や動画（サムネ）を見たくない」**という需要に応えられるなら、ローカルの軽量モデル（`nsfwjs`）では絶対に不可能な領域であり、Jev に画像を送る明確な価値になる。

## 4. フェーズ2：本体への実装計画（実験的機能としての共存・着脱容易化）

### 4.1 設計方針
1. **「実験的機能（Experimental）」として既存機能と共存**
   - 既存のローカル画像認識（`enableImageVision`: `nsfwjs` による露出度判定、デフォルト `ON`）はそのまま維持する。
   - 新たに **`enableJevImageVision`（Jev による画像直接判定・実験的機能、デフォルト `OFF`）** を追加し、設定画面（Options）から個別に ON/OFF できるようにする。
2. **「どちらを捨ててもすぐ剥がせる」疎結合モジュール設計**
   - `background/index.ts` 内のローカル `nsfwjs` 処理を `src/extension/background/localNsfwService.ts` に分離。
   - 新規の Jev 用画像取得・縮小処理を `src/extension/background/jevImageService.ts` に分離。
   - 将来どちらの画像判定を廃止したくなっても、該当サービスファイルを消して呼び出し箇所を1つ外すだけで完結する構造にする。
3. **小サイズ決め打ち（短辺 320px 基準 JPEG・1枚目のみ）**
   - 16:9 等の横長画像でも Jev の最小制限（縦横 280px 以上）を確実に満たしつつ最小サイズになるよう、`OffscreenCanvas` で **短辺 320px（長辺上限 680px、両辺 >= 280px 保証）・JPEG 品質 0.72（約 30KB）** に縮小して 1枚目のみ送信する。
   - 万が一画像付きリクエストが API エラーになった場合は、即座にテキストのみの評価へ自動フォールバックする。
